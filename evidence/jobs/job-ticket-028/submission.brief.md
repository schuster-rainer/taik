Einen angenommenen Sitzungsauftrag per Knopf ins Repository übernehmen, anhand der neuen Felder landable, landing, landed und landFailed.
Im Block THREAD gibt es die reine Funktion landState(job). Fehlt der Auftrag, liefert sie null. Sonst liefert sie { label, text, action }:
- ist job.landed gesetzt: label „Übernommen“, text „Commit “ gefolgt von den ersten 8 Zeichen von job.landed, action false;
- sonst, wenn job.landing wahr ist: label „Übernahme“, text „läuft: zusammenführen, prüfen, installieren“, action false;
- sonst, wenn job.landable wahr ist: label „Übernahme“, text „Gescheitert: “ vor job.landFailed, falls das Feld vorhanden ist, sonst „bereit“, action true;
- sonst null.
Liefert landState einen Wert, zeigt der Stand des Tickets eine weitere Zeile: label ist die Bezeichnung, text der Inhalt. Ist job.landFailed vorhanden und der Auftrag weder übernommen noch in Übernahme, steht diese Zeile in der Farbe der Ablehnungen, var(--bad), und der Text wird nicht abgeschnitten.
Ist action wahr, steht im Ticket neben dem Titel der Knopf „Übernehmen“ mit dem Attribut data-land und dem Namen des Auftrags als Wert. Ein Klick sendet window.webkit.messageHandlers.landJob.postMessage mit diesem Namen als Zeichenkette. Läuft eine Übernahme oder ist der Auftrag übernommen, gibt es den Knopf nicht.
Die Zeile „Als Nächstes“ im Stand lautet für einen Auftrag mit job.landable und ohne job.landing „Übernehmen, damit das Ergebnis im Repository ankommt.“ ticketState(job).next liefert diesen Text. Für alle anderen Aufträge bleibt ticketState unverändert.
Alles andere bleibt, wie es ist.

Die reine Funktion landState steht zwischen den Markern /*THREAD_BEGIN*/ und /*THREAD_END*/ und wird nur mit dem Auftragsobjekt job aufgerufen. Fehlt job, ist das Ergebnis null. job.landed ist gesetzt, wenn der Wert nach String eine Länge größer als 0 hat; dann ist das Ergebnis { label: "Übernommen", text: "Commit " plus die ersten 8 Zeichen von String(job.landed), action: false }, auch wenn landing, landable oder landFailed außerdem gesetzt sind. Sonst ist job.landing wahr, wenn der Wert truthy ist; dann ist das Ergebnis { label: "Übernahme", text: "läuft: zusammenführen, prüfen, installieren", action: false }. Sonst ist job.landable wahr, wenn der Wert truthy ist; job.landFailed ist vorhanden, wenn der Wert nicht null und nicht undefined ist, und text ist dann "Gescheitert: " plus String(job.landFailed), sonst "bereit"; action ist true. Sonst ist das Ergebnis null.
ticketState bleibt die bisherige Funktion im selben Block. Ist job.landable truthy und job.landing nicht truthy, ist ticketState(job).next genau "Übernehmen, damit das Ergebnis im Repository ankommt.", auch wenn die bisherige Logik einen anderen next-Text gesetzt hätte. Ist job.landing truthy oder job.landable nicht truthy, bleibt ticketState(job).next der bisherige Text.
