Füge dem TAIK-Seed den Befehl taik-seed adopt STATE job-NAME hinzu, der den angenommenen Commit einer Agentensitzung als Zweig ins Ursprungs-Repository holt.

Der Befehl liest STATE/jobs/job-NAME/session.repo (Pfad des Ursprungs-Repositorys, ein abschließender Zeilenumbruch ist erlaubt) und die letzte Runde STATE/jobs/job-NAME/round-NN.run. Die letzte Runde ist die Datei mit der höchsten zweistelligen Zahl NN unter den Dateien round-[0-9][0-9].run. Ist die erste Zeile dieser Datei nicht decision=accepted, wird mit Status 2 abgewiesen. Sonst wird die Zeile commit=<SHA> gelesen. STATE/work/NAME ist eine Kopie des Ursprungs-Repositorys und enthält diesen Commit. Aus STATE/work/NAME wird der Commit per git fetch in das Ursprungs-Repository nach refs/heads/taik/NAME geholt. Der Zweig taik/NAME zeigt danach auf diesen Commit.

Bei Erfolg gibt der Befehl taik/NAME auf der Standardausgabe aus und endet mit Status 0. Zeigt taik/NAME bereits auf denselben Commit, ist das ebenfalls Erfolg. Status 2 gilt für: unbekannten Auftrag (kein Verzeichnis STATE/jobs/job-NAME), fehlende Datei session.repo, letzte Runde nicht decision=accepted, und vorhandenen Zweig taik/NAME, der auf einen anderen Commit zeigt. Im Ursprungs-Repository darf der Befehl keinen Zweig wechseln, keine Arbeitsdateien ändern und nichts zusammenführen.

Ergänze in tests/adopt.rs mindestens einen Test, der ein echtes kleines Git-Repository anlegt und den Befehl prüft; cargo test --offline --locked --test adopt muss erfolgreich sein. Ergänze in README.md unter den Befehlen eine Zeile mit dem Text taik-seed adopt STATE job-NAME. Bestehende Befehle und Tests bleiben unverändert.
